# 领域边界

编制气候债券指数族，管理数据水位、方法版本、调仓和重述。

## 参与方与角色

| 角色 | 标识 | 职责 |
| --- | --- | --- |
| 指数编制机构 | `index_provider` | 指数族、日历、运行、发布、（可提议）重述 |
| 气候数据供应方 | `data_vendor` | 行情/披露/事件/基准批次入账 |
| 债券主数据人员 | `master_data` | 发行人、债券、数据来源登记 |
| 方法维护者 | `method_maintainer` | 口径/筛选/权重/方法版本、提出回溯重述 |
| 方法批准人 | `method_approver` | 批准（或驳回）回溯重述，必须为另一角色 |
| 机构投资者 | `investor` | 读取复现报告，不能读受限气候数据 |

## 核心领域规则

### 主数据与指数族

- 发行人、债券、气候数据来源、排放口径、合规筛选、权重方法、方法版本、
  调仓日历均须先登记后使用。
- 一个指数族恰好包含**一个核心指数与六只子指数**。
- 子指数必须与核心**共享同一合规筛选与排放口径**（合格性判断族内共享），
  仅可叠加自身范围过滤（行业、币种、名单、发行量下限）。
- 方法版本号只能严格递增；版本内容不可变；历史版本永远可被历史 run 引用。

### 数据水位与方法版本固定

- 每次计算（run）固定三要素：调仓日、方法版本、**可用数据水位**。
- 水位只纳入知识截止日前送达、且不来自冲突批次的数据；
  披露按"发行人+报告期"取最新版本，行情/基准取不晚于调仓日的最新点。
- 原始计算的知识截止日 = 调仓日（当时知道什么算什么）；
  已批准重述的知识截止日不受限（纳入事后送达的更正数据）。
- 水位清单经规范化哈希后写入 run 快照，永不改变。

### 生效窗口

- 事件（到期、停牌、复牌、评级变化、数据撤回）入账时只登记事件日；
  生效日在**计算时**按该 run 锁定方法版本的窗口解析。
- 默认窗口：到期 0 天、停牌/复牌 1 天、评级变化 5 天、数据撤回 0 天；
  方法版本可覆盖。因此同一历史事件在不同方法版本下可得到不同生效日。

### 权重守恒

- 合格集合由核心筛选统一判定，子指数在其上叠加范围。
- 每个指数（核心或子指数）在**自身成分范围内独立归一**，权重之和恰为 1；
  单券上限通过确定性的迭代再分配实现，残差加到最大权重券。
- 核心合格集为空或封顶不可行时明确失败，绝不伪造权重。

### 批次幂等与异文隔离

- 同编号批次以内容哈希判定：完全重送 → `duplicate`，不重复入账；
  内容不同 → 置 `conflict` 并隔离，阻止与该批次业务日期相关的发布。

### 重述审批（maker-checker）

- 只有方法维护者（或编制机构）可提议回溯重述，且必须填写原因。
- 批准人必须是**另一角色、且非提出人本人**；自批与同角色互批均被拒绝。
- 批准后以当前知识水位与目标方法版本重算，生成独立的 `restated` run，
  原始 run 原样保留，重述影响（碳指标、成分、权重、水位差异）随审批留痕。

### 受限气候数据

- 受限来源的存在性本身保密：无权者对"存在的受限记录"与"不存在的编号"
  收到完全相同的拒绝，跨源检索结果中受限记录整条移除。
- 访问受限来源要求全局受限读权且在该来源的授权角色名单内。

### 调仓任务与故障恢复

- 调仓任务按 `prepare → compute → publish` 三个检查点推进，每步完成即落盘。
- 进程崩溃后用同一状态文件重建服务即可从断点续跑；
  计算以输入指纹去重、发布以 run 编号幂等，恢复不会重复入账。

### 对外复现

- 复现报告不只返回最新数字：它给出某日的方法版本、水位哈希、成分、
  权重、碳指标、基准差异，以及此后每次重述的原因、审批链与影响，
  并指明当前应采用的 run。

资料版本只能递增。参与方、事实和约束均不能为空，示例不得包含真实个人信息、账号或凭据。
