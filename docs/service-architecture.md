# 债券指数编制服务设计

本服务解决的核心问题：**发行人更新一项排放数据后，核心指数、六只子指数与历史披露
若各自按“最新数据/最新方法”重算，机构投资者将无法复现原调仓日超过 19% 的碳强度降幅。**
设计原则是把每一次发布钉死在「数据水位 × 方法版本」上，并让重述成为可追溯、需独立
批准的显式事件。

## 模块

| 模块 | 职责 |
| --- | --- |
| `src/cbi/model.py` | 角色、枚举、评级序、记录工厂与登记校验 |
| `src/cbi/store.py` | 原子 JSON 状态（临时文件 + `os.replace`）与只增任务日志 |
| `src/cbi/access.py` | 角色校验；受限气候数据“存在性不可区分” |
| `src/cbi/windows.py` | 到期/评级/停牌/撤回相对调仓日的生效窗口 |
| `src/cbi/engine.py` | 水位快照、共享合格性、独立权重守恒、碳指标与基准差异 |
| `src/cbi/service.py` | 门面：登记、批次、调仓任务、重述审批、复现报告 |
| `tests/` | 29 项测试，含 19% 降幅端到端场景与崩溃恢复 |

## 登记对象

- 发行人：标识、名称、行业、司法辖区。
- 债券：发行人、面值、到期日、绿色标识。
- 评级事件：按公告日记录，不就地覆盖，配合通知滞后天数生效。
- 停牌/复牌事件：起停牌日与复牌日。
- 气候数据来源与排放披露：来源、报告期、到达日、收入、按口径
  （`S1`/`S12`/`S123`）的排放量、密级（public/restricted）。
- 合规筛选：绿色要求、最低评级、是否要求有排放数据。
- 权重方法：等权 / 市值加权（面值 × 行情/100）。
- 指数族：一个核心指数，子指数通过 `sector` / `min_grade` /
  `max_remaining_years` 维度挂在核心之下，共六只。
- 调仓日历：调仓只能落在已登记日期。

## 每次计算固定的两个坐标

1. **数据水位 watermark**：只有 `received/announced/start <= 水位` 的事实可见。
   评级公告、停牌起/复牌、披露到达、撤回事实都受水位约束——在旧水位下重算时，
   未来才发生的撤回视同尚未发生（`tests` 中
   `test_withdrawal_after_watermark_does_not_change_frozen_run` 锁定此语义）。
2. **方法版本 method key**：排放口径、筛选规则、权重方案、生效窗口参数、基准日
   的不可变组合。草稿不可用于生产计算；版本一经提议必须由**另一角色**
   （`method_approver`，且用户不同于提议人）激活。

基准按**同一方法在基准日重算**，因此“相对基准差异”也是方法相关的。历史数字必须
回到当时的水位与方法版本才能复现——只拿最新数据重算必然得到不同结果。

## 合格性共享，权重各自守恒

`engine.compute_family` 先对全部在册债券做**一次**合格性判断（到期、停牌窗口、
评级窗口、绿色、排放数据），核心与六只子指数共享这份判断；子指数成员恒为核心
合格集的子集（先核心合格，再过维度）。权重则在**各自成员范围内独立归一化**：

- 使用 `fractions.Fraction`，权重和精确等于 1（不是浮点近似）；
- 等权 `1/n`；市值加权 `面值×价 / Σ市值`，缺行情直接拒绝以保证确定性；
- 某子指数成分数变化（如评级剔除）只影响其自身的归一化，不影响其他指数。

## 生效窗口（`windows.py`，均以调仓日 d 为参照）

| 事件 | 规则 |
| --- | --- |
| 到期 | `maturity <= d` 当日退出 |
| 评级 | `公告日 + rating_lag_days <= d` 才生效；窗口内仍按旧评级；取最近一次生效评级 |
| 停牌 | 停牌起 `suspension_grace_days` 个自然日内保留；超期且未复牌则退出；复牌日（含）恢复 |
| 数据撤回 | 撤回起 `withdrawal_cure_days` 补救期内旧值仍可用；超期视为缺失；重述新版本批准后直接用新版本 |

停牌事件的“复牌”事实若晚于水位，按仍未复牌处理，避免未来信息泄漏。

## 批次：重送不重复入账，异内容阻断发布

`submit_batch` 以 `batch_id` 为幂等键，对条目做与键顺序无关的 SHA-256 指纹：

- 重送且指纹一致 → `replayed`，不重复写行情/披露，交付计数增加；
- 重送但指纹不同 → 批次置 `blocked`，所有消费该批次的**已发布运行**标记为
  `blocked`，并阻止后续消费该批次的发布（发布前检查输入批次状态，抛 `BatchBlocked`）。
  复现接口对被阻断的权威发布显式报错，而不是静默给出数字。

## 调仓任务与故障恢复

任务有 `pending → running → done/failed` 生命周期与检查点
（`created → started → computed → published`），每个状态迁移写一条只增
`tasks.jsonl`（fsync）。状态原子落盘，崩溃只可能留下旧版或新版。

`recover_interrupted` 扫描落盘中的悬挂任务并重放：计算是水位+方法下的确定性纯
函数，任务号/运行号沿用，**不会产生重复运行或重复发布**。测试用 `crash_after`
注入“计算前”和“计算后发布前”两种崩溃。

## 重述：提议与批准必须分离

- 方法维护者（`method_owner`）提议数据重述或方法重述，记录原因；
- 必须由 `method_approver` 且**非提议人本人**批准；同一用户同时拥有两个角色仍被
  拒绝（职责分离看用户身份而非角色集合）；
- 数据重述批准后才生成新版本披露（`version + 1`，`received = 批准日`），旧版本
  标 `superseded_by` 但永不删除；新版本在历史水位下不可见；
- 方法重述批准后旧版本停用，新计算不能再引用，但旧快照可用冻结版本审计复现。

重算历史调仓日通过 `run_restated_view` 产生带 `restated:<id>` 标签的**独立运行**，
绝不覆盖原始冻结发布。

## 受限气候数据：存在性也不可确认

- 无权角色直取受限记录与查询不存在的记录得到**同类型、同文案**错误
  （`NotFound: 气候数据不存在或不可见`）；
- 搜索结果直接剔除受限记录，无法用“结果存在与否”推断；
- 复现报告对无权投资者：受限成分的强度/记录标识脱敏，合格性审计行一并脱敏；
  指数级 WACI 仍按完整数据计算（指数编制结果），成分级数值不泄露。

## 复现报告：返回“某日的冻结事实”，不是最新数字

`reproduce(run_id | rebalance_date)` 默认返回该调仓日 **original 冻结发布**：
固定水位、方法快照、成分、权重（精确分数+十进制展示）、各成分碳强度、
WACI、基准 WACI、相对基准降幅、与核心差异、输入批次、共享合格性审计，以及
`later_restatements`——发布之后经批准、影响到所用记录/方法的重述及其原因、提议人、
批准人。被重述成分逐行标记 `restated_afterward`。想看重述视角必须显式传 `run_id`，
无法在默认路径上“只拿到最新数字”。

## 角色矩阵

| 角色 | 主要权限 |
| --- | --- |
| `data_steward` | 发行人/债券/评级/停牌/行情、指数与维度登记 |
| `climate_provider` | 气候来源、披露登记与撤回、披露批次 |
| `method_owner` | 提议方法版本、提议重述（**不能**自行批准/激活） |
| `method_approver` | 激活方法、批准/驳回重述（须为不同用户）；可见受限数据 |
| `index_calculator` | 调仓日历、执行/恢复调仓、审计复算；可见受限数据 |
| `investor` | 复现报告、运行清单；受限数据存在性不可见 |
